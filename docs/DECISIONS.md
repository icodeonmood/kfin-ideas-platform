# Decisions

What has been decided, by whom, and why. Claude Code adds build decisions at the bottom (the next ID in its lane, newest last). Anything in **Product decisions** needs the product lead's agreement to change.

**Status:** `Decided` — settled. `Default` — applied until the named owner confirms or overrides. `Open` — see `ARCHITECTURE.md` §11.

## IDs when several sessions build at once (BLD-A161)

**Build decisions carry a lane letter:** `BLD-A161`, `BLD-B230`, `BLD-C001`. Each lane counts on by itself, so lanes never have to agree on a number and there is no ceiling. Lanes A and B carry on from their last plain number. A new lane starts at 001.

**Old IDs stay as they are.** Plain numbers stopped at BLD-160 (lane A) and BLD-229 (lane B). Code, tests and commit messages cite those IDs.

**Product decisions keep one sequence** (DEC-096, DEC-097, and on), because they are the numbers the product lead refers to. Add a DEC row only on `main`, straight after `git pull --rebase`. Commit that file on its own and push at once.

**From a worktree, do this without touching the main checkout,** which other sessions share:

1. Commit your own work first.
2. Run `git fetch origin && git switch --detach origin/main`.
3. Add the row and commit.
4. Run `git push origin HEAD:main`.
5. Run `git switch -` and rebase.

Never run `git reset`, `git stash` or a whole-file `git add` in a checkout another session is using.

**A new session claims a lane** by taking the next free letter and adding a row below on `main` before it writes its first build decision.

**`make lint` checks all of this** (`scripts/ci/check_decision_ids.py`). It fails on any of these:

- an ID used twice;
- a malformed ID;
- an unregistered lane letter;
- a new plain-number build ID.
